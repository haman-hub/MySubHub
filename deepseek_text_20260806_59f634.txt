## How It Works (Architecture)
- **Bot webhook** is handled by Express. All bot commands (like `/start`) are processed.
- **API endpoints** are secured with Telegram `initData` validation.
- Payment flow:
1. User selects a channel, clicks “Pay with TON”.
2. Frontend requests a unique memo from backend.
3. TON Connect pops up and user signs a transaction to the admin wallet.
4. Frontend sends the signed `boc` to backend.
5. Backend verifies the transaction on‑chain (via TON Center), records subscription and platform fee, and the bot sends an invite link to the user.
- **Platform fee** (1%) is deducted from the total and tracked. The owner’s 99% stays as pending earnings until they request a withdrawal, which the admin can approve and pay out manually via the admin wallet.

## Security Considerations
- Never expose the `SUPABASE_SERVICE_ROLE_KEY` in the frontend. Only the backend uses it.
- The `BOT_TOKEN` must be kept secret; it’s used to validate `initData`.
- For payout automation, the admin wallet private key should be stored in Render environment variables (not committed). In this template, `payout()` is a stub; implement a secure signing service or use a custodial wallet API.
- Row‑level security on Supabase ensures that even if the anon key leaks, users can only see their own data.
